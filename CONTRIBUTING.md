# Contributing · 参与贡献

感谢你帮助改进 ClaudeU Labs 的公开工具和文档。贡献只应针对对应公开仓库声明的范围；ClaudeU Desktop 商业产品、账户、支付、网关和托管服务不在公开贡献范围内。

Thank you for improving ClaudeU Labs public tools and documentation. Contributions must stay within the scope declared by the affected public repository. The proprietary ClaudeU Desktop product, accounts, payments, gateway, and hosted services are outside the public contribution scope.

## Before opening an issue or pull request

1. Search existing issues and pull requests.
2. Read the affected repository's README, license, support policy, and security policy.
3. For a bug, include the smallest reproducible example, operating-system version, tool version, expected result, and redacted actual result.
4. For a documentation change, identify the audience, the problem it solves, and the evidence for time-sensitive claims.
5. Use private vulnerability reporting for security issues. Never disclose an exploitable issue in a public ticket.

## Contribution boundaries

Do not submit:

- credentials, API keys, tokens, cookies, certificates, private keys, account data, or customer data;
- raw user profiles, browser profiles, logs, crash dumps, screenshots, UI automation trees, or diagnostic bundles containing personal or machine-identifying data;
- official Claude Desktop binaries, installers, runtimes, `app.asar`, extracted or patched official files, official icons, screenshots, localized strings, or other Anthropic assets;
- code or instructions presented as bypassing account, payment, subscription, regional-availability, access-control, integrity, update, or service-policy requirements;
- unverifiable claims of official affiliation, endorsement, certification, partnership, performance, compatibility, or availability;
- copied material without a compatible license and complete attribution.

Use synthetic examples and placeholders such as `example.invalid`, `<token>`, and `<user-path>`. Before attaching output, remove usernames, home-directory paths, IP addresses, machine identifiers, request identifiers, and secret values.

## Pull request expectations

A focused pull request should:

- explain the user-visible problem and the chosen change;
- keep unrelated changes out of the diff;
- add or update the smallest relevant test or validation;
- verify Markdown links and commands where applicable;
- update documentation when behavior or support boundaries change;
- identify every third-party source and license;
- avoid official assets and proprietary ClaudeU product code;
- pass the repository's documented checks.

By contributing, you certify that you wrote the contribution or otherwise have the right to submit it, and that it may be distributed under the affected repository's license. A public contribution does not grant rights to the ClaudeU name, visual identity, commercial product, or third-party marks.

Maintainers may close contributions that are out of scope, unsafe, promotional, unverifiable, or incompatible with the repository license. Product support requests should use the contact route on the [ClaudeU homepage](https://claudeu.com/?utm_source=github&utm_medium=organic&utm_campaign=claudeu-labs&utm_content=contributing-product-support), not a public code issue.
